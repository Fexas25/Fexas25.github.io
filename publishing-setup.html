写作与发布

服务已配置，日常更新直接使用写作页 →

  • 新内容：新建草稿，选择栏目并填写正文，登录 GitHub 后发布。
  • 修改：展开“打开已有文章 · GitHub 登录”，选择内容，打开修改后保存。
  • 配图：放好光标，点“上传图片”；公开图片上传到仓库，私密图片随正文保存。
  • 换设备：在“导入与备份”下载全部草稿，在新设备恢复。草稿只自动保存在当前浏览器。
  • 密钥访问：新建时选择该模式，发布后保存链接和密钥。可重新编辑或换密钥；内容不会进入公开列表、搜索或订阅。私密 Markdown 导出是本地明文副本，不要上传公开仓库。

公开内容提交后需要等待自动检查与部署完成；私密内容保存后立即生效。登录状态不随草稿备份，刷新后需重新登录。

遇到问题
  • 登录窗口没打开：允许本站弹出窗口，再试一次。
  • 提示权限不足：检查 GitHub App 是否安装在网站仓库，Contents 权限是否为读写。
  • 提示远端内容已改变：先导出当前草稿，再打开最新内容合并，避免覆盖新修改。
  • 网络中断：保留草稿，恢复网络后重试。公开发布与图片上传会先检查是否已提交。
  • 密钥遗失：登录，打开对应私密内容，再更换密钥。旧密钥随即失效。
维护与迁移

登录服务为 mx-writing-auth，代码和配置位于仓库 _publishing/；前端公开地址位于 editor-config.js。

Fexas25 MX Writing 只安装在网站仓库，使用 Contents 读写与 Metadata 只读权限。回调为登录 Worker 地址加 /callback，当前流程不需要 Private key。

Worker 使用 GITHUB_CLIENT_ID 变量和 GITHUB_CLIENT_SECRET Secret。密钥只留在 Cloudflare，不放入仓库或草稿。迁移时同步更新 GitHub App 回调与前端地址。

私密正文与访问密钥摘要存放在 mx-community 的 D1 中，详见留言、翻译与私密服务说明。不要把已公开内容直接当作私密内容，旧版本可能仍保留在公开仓库历史里。
